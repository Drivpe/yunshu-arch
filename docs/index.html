云枢 (YunShu) for Arch Linux

社区维护的 pacman 仓库 · 非厂商官方发行版

与官方安装包的重要差异
本包不含 DLP 数据防泄漏、截图审计、厂商自更新器与内核级 hook。 如果你的公司要求通过云枢接受合规审计，本包无法满足，请使用厂商官方安装包。

安装

在 /etc/pacman.conf 末尾加入：

[yunshu]
Server = https://ghfast.top/https://github.com/Drivpe/yunshu-arch/releases/latest/download
Server = https://github.com/Drivpe/yunshu-arch/releases/latest/download
SigLevel = Optional TrustAll

第一行是国内加速镜像，第二行是官方源兜底；代理失效时 pacman 自动回落。 若你在海外或不想用第三方代理，删掉第一行即可。

关于 SigLevel
本仓库未做 GPG 签名，所以必须加这一行，否则 pacman 会因「缺少签名」拒绝安装。 TrustAll 表示信任此仓库的全部内容 —— 由于包是本仓库从厂商 CDN 拉取并原样重建的， 且你在安装前可自行核对 sha256，这个取舍在本场景下是合理的。 若你不接受放宽签名策略，请改用下方的「自行构建」方式。

然后安装：

sudo pacman -Sy
sudo pacman -S yunshu
如果提示 包未找到，先确认 pacman -Sy 没有报错。 数据库文件在同一个 Release 中，与包一起更新。

或者：自行构建

不想放宽签名策略的话，直接拿 PKGBUILD 自己构建（需要 base-devel）：

git clone https://github.com/Drivpe/yunshu-arch.git
cd yunshu-arch
makepkg -si

这样包由你本机构建，不经过任何第三方签名校验。

安装后

安装过程中会询问是否启用后台服务，回车即启用。若当时跳过了：

sudo systemctl enable --now yunshu-daemon

启动图形界面：

yunshu

或从应用菜单搜索「云枢 / YunShu」。

首次登录需填写「企业标识」，请向你的企业 IT 管理员索取。

卸载

除了卸包，还要清掉安装时写进 /etc/pacman.conf 的仓库段。 用仓库里的脚本一次做完：

curl -fsSL https://raw.githubusercontent.com/Drivpe/yunshu-arch/main/uninstall-yunshu.sh | sudo bash

会依次停服务、pacman -Rns、移除 [yunshu] 段（自动备份）、 清理同步缓存与手工安装遗留。

连登录凭证一起删：

curl -fsSL https://raw.githubusercontent.com/Drivpe/yunshu-arch/main/uninstall-yunshu.sh | sudo bash -s -- --purge

会清理程序文件、系统集成项，以及 /opt/apps/yunshu 下含登录凭证的 config.db 与策略缓存。

以下目录保留（遵循 Arch「包不碰家目录」惯例）：

~/.config/YunshuCross/

该目录含 Cookies 与登录态。要连同凭证彻底清除：

rm -rf ~/.config/YunshuCross

常见问题

沙箱启动失败？
本包不给 chrome-sandbox 设 setuid，改用内核的 unprivileged userns。 若你的系统禁用了它（kernel.unprivileged_userns_clone=0）， 可复制一份 desktop 文件到 ~/.local/share/applications/， 在 Exec= 末尾加 --no-sandbox。

版本落后？
厂商没有公开的 Linux 下载页，版本探测依赖其公开接口，可能滞后。 发现新版请在本仓库开 issue。
